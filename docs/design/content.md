# コンテンツ管理の設計

記事、メモ、固定ページを Markdown で管理するための設計。画像と動画の保存・配信は [media.md](./media.md) に分けている。

## 前提

- Astro 7 の静的生成。サーバー側の描画は使わない
- コンテンツは `.md` だけで書く。MDX は使わない（`@astrojs/mdx` は外す）
- スキーマは Valibot
- 日時はすべて日本時間として扱う
- 旧サイト（`sendo-kakeru/bowling-lab_old`、EmDash 製）の記事とメモは移行しない
- 見た目は現時点では忠実に再現しない。この設計の範囲は、データの形、URL、HTML の出力まで

## ファイルと URL

| | 記事 | メモ |
|---|---|---|
| 置き場所 | `src/content/posts/<スラッグ>.md` | `src/content/memos/YYYY-MM-DD-HHmm.md` |
| 作成時の名前 | `_k3f9.md`（`_` + ランダム 4 文字） | 作成日時 |
| id | ファイル名（拡張子を除く） | ファイル名（拡張子を除く） |
| 詳細 | `/posts/<スラッグ>` | なし |
| 一覧 | `/posts`、`/posts/page/2` | `/memos`、`/memos/page/2` |
| 1 ページの件数 | 20 | 20 |

- URL は末尾スラッシュなしで統一する（`/posts`、`/posts/page/2`）
  - Astro: `trailingSlash: "never"`。canonical、サイトマップ、`Astro.url.pathname` がスラッシュなしになる
  - Cloudflare: `wrangler.jsonc` の `assets` に `"html_handling": "drop-trailing-slash"` を書く。ビルドの出力は `posts/index.html` で、既定の設定のままだと `/posts` が毎回 `/posts/` に転送される。サイトは表示されるので気づきにくい
- ページ番号はパスに入れる。静的生成ではクエリパラメータで中身を変えられない
- 1 ページ目は `/posts` と `/memos` だけで、`/page/1` は作らない
- `/posts/2` ではなく `/posts/page/2` にするのは、詳細ページの URL と紛れないようにするため。メモに詳細ページ（`/memos/<id>`）を足すときも被らない
- ホームには最新の記事 3 件とメモ 2 件を出す

## 記事

```md
---
title: 10番ピンが残る理由
description: 手首の返りと親指の抜けを動画で見比べた。
publishedAt: 2026-11-15
thumbnail: media:2026/ten-pin/lane.jpg
---

本文…
```

| 項目 | 必須 | 用途 |
|---|---|---|
| `title` | ○ | 見出し、カード、`<title>` |
| `description` | | カードの抜粋、meta description。省略時は本文の冒頭から作る |
| `publishedAt` | ○ | 公開日、並び順。日付だけ（時刻は持たない） |
| `thumbnail` | | 一覧と OGP の画像。`media:` の論理パスで書く |

### スラッグと下書き

- ファイル名がそのまま URL になる。英小文字、数字、ハイフンだけを使う。`page` は一覧のページ送りとぶつかるので使えない
- `_` で始まるファイルは下書き。本番ビルドには含めず、開発サーバーでだけ `/posts/_k3f9` で表示する
- 公開は `_` を外して名前を付けることだけで決まる。`publishedAt` が未来の日付でも隠さない
- 公開後に名前を変えると旧 URL が切れる。変えたら転送の設定を足す

### 並び順

`publishedAt` の新しい順。同じ日付の記事はファイル名の昇順。

### サムネイル

次の順で決める。

1. フロントマターの `thumbnail`
2. 本文の最初の画像
3. 既定の画像（`src/assets/` に置く）

- 一覧のカードでは画像の隣にタイトルがあるので、`alt` は空にする。代替テキストの項目は持たない
- 記事ページの冒頭に出すのは、`thumbnail` を明示したときだけ。本文の最初の画像で代用した場合は冒頭に出さない（同じ画像が 2 回並ぶため）

### 本文から求めるもの

読了時間と目次は本文から求める。項目としては持たない。

## メモ

記事にするほどでもない短い書き込み。あとから続きを足せる。

```md
## 2026-11-06 21:14

10番ピンだけ残るとき、たぶん手首が先に返っている。

## 2026-11-06 21:38

動画を撮ってみたら、手首より先に親指の抜けが遅れていた。

## 2026-11-08 15:20

親指を早めに抜くつもりで 3 ゲーム。10番ピンが残ったのは 2 回だけ。
```

- `## YYYY-MM-DD HH:mm` の行だけが書き込みの区切り。コードブロックの中にある同じ形の行は区切りにしない
- 先頭がメモ本体、2 つ目以降が続き
- フロントマターと下書きはない
- 並びは先頭の書き込みの日時の新しい順。続きを足しても順番は変わらない
- ファイル名は作成時の日時のままにする。あとで見出しの日時とずれても、表示と並び順には見出しの日時だけを使う

### データ構造

```ts
type MemoNote = { postedAt: Date; html: string };
type Memo = { id: string; notes: [MemoNote, ...MemoNote[]] };
```

- 最初の書き込みと続きは同じ形。先頭と続きを分けるのは表示側で行う（`const [first, ...rest] = memo.notes`）
- `notes` は 1 件以上。Valibot の `tupleWithRest` で型にも出す
- 旧サイトの `publishedAt`、`text`、`replies` は EmDash の形に合わせたものなので引き継がない

### 処理の流れ

1. `parseMemo`（純粋関数、単体テストあり）: 本文を区切りごとに分け、`{ postedAt: string, markdown: string, line: number }` の配列にする。書式の誤りは行番号つきで落とす
2. Valibot: 日時の文字列を `Date` に変換し、存在しない日時と日時の逆転を落とす
3. `memoLoader`（独自のコンテンツローダー）: 書き込みごとに `renderMarkdown` で HTML にして `store.set` する。開発中は `watcher` でファイルの変更を拾って読み直す
4. `getMemos()`: 新しい順の `Memo[]` を返す

標準の `glob` ローダーは 1 ファイルを「フロントマター + 本文 1 つ」としてしか扱えないので、メモだけ独自のローダーにしている。`renderMarkdown` は記事と同じ Markdown の設定で変換するので、HTML の出力は記事と同じになる。

### ビルド時の扱い

| 状態 | 扱い |
|---|---|
| 最初の見出しより前に文がある | エラー |
| 日時が存在しない（`2026-13-40` など） | エラー |
| 日時が前の書き込みより古い | エラー |
| 途中の見出しの下が空 | エラー |
| 末尾の見出しの下が空 | 読み飛ばす。見出しだけのファイルはメモとして出さない |

末尾の空の見出しを許すのは、`pnpm memo` と `pnpm memo:add` が見出しだけを先に書くため。

### 記事との違い

- 見出しに id を付けない。一覧では複数のメモが 1 ページに並ぶので、同じ文言の見出しがあると id が重なる

## 固定ページ

`src/content/pages/` に置く。

| ファイル | 内容 |
|---|---|
| `about.md` | 本文に紹介文。フロントマターに BOWLER CARD の項目（名前、投げ方、マイボール、ホームセンターなど） |
| `privacy.md` | プライバシーポリシー |

文言は md に、レイアウトはコンポーネントに置く。

## サイト設定

サイト名、タグライン、メニュー、SNS のリンク、メディアの配信用ドメインは `src/consts.ts` に書く。

## スキーマと型

Astro 7.4.12 の `defineCollection` の `schema` は Zod 専用で、Valibot のスキーマは渡せない（内部で `_zod` を持つかを検査している。ローダーの `createSchema` も同じ）。そのため次の形にする。

- コレクションには `schema` を渡さない
- 検証は Valibot で行う。メモはローダーの中で、記事と固定ページは取得関数の中で行う
- ページとコンポーネントは `getCollection` を直接呼ばず、取得関数（`getPosts()`、`getMemos()` など）だけを使う。型は `v.InferOutput` から付ける

画像は `media:` の参照で書くので、Astro の `image()`（Zod のスキーマの中でしか使えない）は不要。

## Markdown の変換

記事、メモ、固定ページで同じ設定を使う。次の 2 つを変換に足す。

### メディアの参照

`![](media:2026/kyoto/cat.jpg)` を manifest で解決して `<img>` か `<video>` にする。詳細は [media.md](./media.md)。

### 外部の埋め込み

URL だけを 1 行に書くと埋め込みになる。

```md
https://www.youtube.com/watch?v=xxxxxxxxxxx

https://www.instagram.com/reel/xxxxxxxxxxx/
```

| | 出力 | 補足 |
|---|---|---|
| YouTube | `youtube-nocookie.com` の `<iframe>` | 通常の動画は 16:9、ショートは 9:16。遅延読み込み |
| Instagram | 投稿 URL に `/embed` を付けた `<iframe>` | 投稿とリールに対応。公式の埋め込みスクリプトは読み込まない |

Instagram は高さを中身に合わせて自動調整できないので、固定の比率で枠を取る。実際の表示は実装時に確かめる。

## コマンド

| コマンド | 動き |
|---|---|
| `pnpm memo` | 今の日時の名前でメモを作り、今の日時の見出しを書く |
| `pnpm memo:add` | いちばん新しいメモの末尾に、今の日時の見出しを足す |
| `pnpm memo:add <id>` | 指定したメモの末尾に足す |
| `pnpm post` | `src/content/posts/_xxxx.md` を、フロントマター（`title` は空、`publishedAt` は今日）つきで作る |

- どのコマンドも文は受け取らない。見出しとファイルを用意するだけで、文はエディタで書く
- `memo:add` は、末尾の見出しの下が空なら見出しを足さず、その日時を今に書き換える
- `pnpm memo` は、いちばん新しいメモが見出し 1 つだけで文なしなら、新しく作らずそのファイルの見出しとファイル名を今の日時に直す
- 同じ分にメモを 2 件作った場合は、ファイル名に `-2` を付ける
- 見出しの日時の書式は `parseMemo` と同じ定数と関数を使う
- 書いたファイルのパスを表示する。コミットはしない
- スクリプトは `scripts/` に置き、Node で `.ts` をそのまま実行する

メディアのコマンド（`pnpm media:push`）は [media.md](./media.md)。

## 作らないもの

| 項目 | 方針 |
|---|---|
| 検索 | 作らない。足すならビルド時に索引を作る方式（Pagefind など）。生成済みの HTML から作るので、コンテンツの形は変えずに足せる |
| RSS | 記事だけ。メモは入れない |
| メモの個別ページ | 作らない。足すなら `/memos/<id>` |
| タグ・カテゴリ | 作らない。足すなら任意の項目として |
| 更新日（`updatedAt`） | 持たない |

## 仮データ

動作確認用に、分岐を一通り確かめられる量を置く。

| 種類 | 件数 | 含めるもの |
|---|---|---|
| 記事 | 25 件前後 | `thumbnail` あり / なし（本文の画像で代用）/ 画像なし（既定の画像）、`description` あり / なし、見出しが多く目次が出る長文、画像・動画・YouTube・Instagram 入り、同じ日付の複数記事、`_` つきの下書き |
| メモ | 45 件前後 | 続きが 0〜4 件、本文にリンクやリストや画像を含むもの、末尾が空の見出しで終わる書きかけ、見出しだけのファイル |
| 固定ページ | 2 件 | About（BOWLER CARD つき）、プライバシーポリシー |

- エラーになるはずの書き方は、コンテンツには置かず単体テストで確かめる。置くとビルドが通らなくなる
- R2 のバケットはまだないので、仮データが参照するメディアは manifest に手書きで入れる。URL の組み立てと HTML の出力までを確かめ、画像と動画そのものは表示されない

## 実装の分け方

PR ごとに issue を分けている。仮データは最後にまとめず、それぞれの PR で自分の範囲のぶんを足す。

| issue | 作業 | 先に必要なもの |
|---|---|---|
| #16 | 土台: テンプレートの整理、MDX を外す、Valibot、テスト、型チェック、`src/consts.ts`、ページ送りの共通部品、manifest の土台 | なし |
| #17 | 記事: コレクション、`getPosts()`、一覧とページ送り、詳細、下書きの扱い、RSS | #16 |
| #18 | メモ: `parseMemo`、ローダー、`getMemos()`、一覧とページ送り、ホームの最新 2 件 | #16 |
| #19 | 固定ページ: About、プライバシーポリシー | #16 |
| #23 | メディアの CLI: `media:push` | #16 |
| #20 | コマンド: `memo`、`memo:add`、`post` | #17、#18 |
| #21 | 外部の埋め込み: YouTube、Instagram | #17、#18 |
| #22 | メディアの参照解決: manifest を引いて `<img>` / `<video>` を出す。サムネイルの決定 | #17、#18 |

- #16 を最初に行う
- #17、#18、#19、#23 は #16 のあとなら並行して進められる。#17 と #18 はどちらもホーム（`/`）を触るので、あとからマージするほうで取り込む
- #21 と #22 はどちらも Markdown の設定（`astro.config.mjs`）を触るので、どちらかを先にマージする

移植元になる旧サイトのコンポーネントは `MemoSlip`、`MemoList`、`LatestMemos`、`PostCard`、`PostList`、`PostDetail`、`Pagination` など（`sendo-kakeru/bowling-lab_old` の `src/components/`）。
